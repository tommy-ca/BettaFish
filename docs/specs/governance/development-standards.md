# Development Standards

## Branching & Workflow
- **Naming:** `feature/<scope>`, `fix/<scope>`, `chore/<scope>`; include Jira ticket when available.
- **Reviews:** Minimum of 2 approvals for production-impacting code, 1 for docs-only.
- **CI Gates:** Lint, tests, type-check, doc build, and security scan must pass before merge.
- **Release Cadence:** Weekly release branch cut on Tuesdays 18:00 PT with release owner assigned in OpsGenie.

## Coding Expectations
- Follow patterns defined in `implementation/code-patterns.md`.
- Enforce strict typing (`from __future__ import annotations`, mypy strict).
- Prohibit global mutable state outside DBOS workflows; use dependency injection via factories.
- API/Schema changes require simultaneous update to `interfaces/` specs and autogenerated docs.

## Documentation Requirements
- Every feature PR must update relevant markdown specs and operator runbooks.
- Architectural decisions captured in ADR format under `docs/adr/ADR-<id>.md` with reversible reasoning.
- Include screenshots or Loom demos when UI/UX changes exceed cosmetic adjustments.

## Localization & Accessibility
- User-facing content supports English + Chinese; updates require translation issue tracked in backlog.
- Streamlit screens must meet WCAG 2.1 AA contrast and keyboard navigation requirements.

## Review Checklist
1. Tests cover new code paths and edge cases.
2. Telemetry fields (trace IDs, request IDs) remain intact.
3. Secrets are sourced from config abstractions, never hard-coded.
4. Rollback plan documented for risky migrations.

## Acceptance Criteria
- 100% of merged PRs have passing CI evidence and completed review checklist.
- Documentation and ADR updates are present for architectural changes.
- Accessibility validations are recorded for UI work.
